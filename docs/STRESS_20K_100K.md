# 20K/100K 压测诊断（2026-11-18）

## 多源 IP + 重试 + 限速 ramp

- `LOAD_SOURCE_IPS=N`：客户端绑定 `127.0.0.x` 分散源端口；
- 失败连接最多重试 3 次；
- `LOAD_RAMP_MS`：在指定窗口内逐步建连，避免 SYN 风暴。

## 结果（单节点，单流 live/test）

| 方式 | 目标 | 成功 | 失败 |
|---|---|---|---|
| 2 IPs，立即 20K | 20,000 | 7,960 | 12,040 |
| 2 IPs + 重试 | 20,000 | 10,546 | 9,454 |
| 2 IPs + 重试 + 12s ramp | 20,000 | **15,102** | 4,898 |

## 结论

单节点在约 **15–16K 并发 TCP 连接**附近达到上限，多源 IP 与限速建连
只能接近该上限，不能突破。100K 需要多节点/多主机分流，而非单节点优化。

未将 20K/100K 标为通过。

## 双节点 20K 尝试（2026-11-18）

- `LOAD_TARGETS=127.0.0.1:8180,127.0.0.1:8181` 轮询分流；
- 6 个源 IP，15s ramp；
- 结果：`ok=12943 / 20000`。

两节点同时在线仍只有 ~13K 成功，说明瓶颈在**单机客户端/OS 连接上限**
（约 15–16K），不是单节点服务端；100K 需要多台压测主机。
## 多进程 20K（2026-11-18）

4 个 Node 进程，各 5000 连接、独立源 IP、10s ramp：

```text
3892 + 3774 + 4786 + 757 = 13209 / 20000
```

再次确认瓶颈是**主机级连接上限**（约 13–16K），不是单进程或单节点。
100K 必须跨主机。
