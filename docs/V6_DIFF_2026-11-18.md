# Monibuca V6 对标复核（2026-11-18）

> 范围：当前 `m7s-rs` 工作区（31 个 crate：5 个 foundation + 26 个插件）与 Monibuca V6 官方能力/性能声明逐项对照。
>
> 说明：`docs/` 下早期对标文档（`MONIBUCA_V6_PARITY.md`、`PROTOCOL_MATRIX_V6.md`、`V6_GAP_ANALYSIS_2026-11-17.md`）已明显过期且部分为乱码；本文以当前代码与最近测试结果为准。

## 1. 结论

**核心数据面与插件数量已基本对齐，但不能宣称“完全对标 V6”。**

- 已对齐：workspace 分层、26 个插件 crate、lock-free Ring + 每流 Dispatcher、10K 真实流、10K viewers、SRT/AES、RTSP TCP/UDP 音视频、HLS TS/fMP4/LL/master 多码率、WebTransport 双向流 ingest、**WHEP 媒体面（webrtc-rs 客户端）**、Admin/Web SDK/gRPC/DB/Room 基础、QUIC relay/心跳/故障切换 + HTTP 故障切换。
- 硬缺口：**SVC 未实现**、**100K 未验证**。
- 深度缺口：TWCC 真实弱网、LL-HLS fMP4 加密/byte-range、GB28181 真机/录像、RTSP backchannel/组播真机、ONVIF 真机、Room/Live/Meeting 完整业务、官方商业授权模型（在线激活/计费）。

## 3. 主要差异（按严重度）

### P0：阻断“完全对标”的硬缺口

| 差异 | V6 官方/目标 | 当前状态 | 证据/说明 |
|---|---|---|---|
| WHEP/WHIP 媒体面 | 浏览器/FFmpeg 可实际收发音视频 | **WHEP egress 与 WHIP ingest RTP 均已通**（webrtc-rs 客户端）；根因是测试客户端 `nat_1to1_ips` 破坏候选；浏览器/FFmpeg 互操作与 30s 稳定性未验收 | `tests/whep_media.rs`、`tests/whip_media.rs`、`tests/webrtc_offer.rs` |
| SVC | 多层空间/时间可分层选择 | NAL 14/20 解析 + RTSP dependency 过滤；无 SVC 编码器；`svc:false` | `docs/SVC_OPTIONS.md` |
| 100K 并发 | 单集群 100K+ | 单机主机级 TCP 上限约 13–16K；双节点/多进程仍约 13K；100K 未验证 | `docs/STRESS_20K_100K.md`：15,102/20,000（单节点），12,943/20,000（双节点），13,209/20,000（4 进程） |

## 4. 性能差异

| 指标 | V6 官方声明 | 当前实测 | 结论 |
|---|---|---|---|
| 单帧写入 | ~100 ns | Ring 写入 ≈ 117.2 ns | 同量级，需同机同场景复测 P50/P99 |
| 订阅者读取 | ~50 ns | 未单独基准 | 缺基准 |
| 单节点并发流 | 10,000+ | 10,000 真实 RTMP 流 | 达标（但内容相同、FFmpeg tee） |
| 单流订阅者 | 10,000+ | 10,000 HTTP-FLV viewers，约 16 s | 达标 |
| 慢订阅者 | bounded 150 + 丢帧 | 已实现 + drop 计数 | 对齐 |
| 大规模流 | >100 流启用 DispatcherPool | 已实现（`M7S_DISPATCHER_WORKERS`） | 对齐 |
| 100K/1M | 官方集群能力 | 未验证；单机 ~13–16K | 未达标 |

注意：10K 真实流使用同一 FLV 经 40 个 FFmpeg tee 复制，不等价于 10K 独立摄像头/异构码流；100K 需要多台压测主机。

## 5. 修复规划

> 估算按 1 名熟悉 Rust/媒体的工程师全职；不含外部资源等待。每项以“可重复测试 + 可观测指标”收口。

### P0（先恢复“可宣称对标”的资格，1–2 周）

1. **WHEP/WHIP 媒体面**（webrtc-rs 端已通；剩余 1–2 天互操作验收）
   - 已完成：`tests/whep_media.rs` WHEP ICE Connected + 收到 RTP；`tests/whip_media.rs` WHIP 上行 RTP → FLV tag；
   - 根因：测试客户端设置 `set_nat_1to1_ips`，候选地址被改写，服务端无法配对；
   - 剩余：Chrome/FFmpeg 实际 WHEP 播放、WHIP 上行互操作、30s 稳定性。
2. **SVC**（5–10 天，需外部编码器决策）
   - 方案 A：外部 SVC 编码器多层 RTP，按 RID 转发；
   - 方案 B：服务端转码分层（成本高）；
   - 不允许再以 `svc:false` 宣称支持；
   - 验收：2 层码流、客户端切层无黑屏、自动化测试。
3. **100K 压测**（3–5 天 + 多主机）
   - 多主机/容器编排，每台 ≤8–10K 连接；
   - 输出成功率、CPU/RSS、带宽、P99；
   - 验收：100K subscribers 或明确报告瓶颈。
4. **QUIC cluster 故障切换**（已完成）
   - origin `@ping` 心跳；双 origin 发现；edge 失败后 500ms 轮换；
   - `tests/quic_failover.rs`：kill A 后同一 viewer 继续收到 B 的字节。

### P1（协议深度与工程边界，2–4 周）

5. TWCC per-packet：发送历史 + arrival delta + 队列延迟修正；loss/jitter 模拟已补，真实弱网仪表待测（1 天）。
6. LL-HLS：blocking、PART/PRELOAD-HINT、part 路由、master 多码率、TS/fMP4/part AES、fMP4 Range 已完成；真实 ABR 待补（1 天）。
7. GB28181：PlaybackControl/RecordInfo 信令已补；真实 Catalog/录像内容、PTZ 闭环、真机联调待补（5–7 天）。
8. SRT/WT egress、RTSP Digest/multicast 协商/客户端 A/V pull、ONVIF 服务端+客户端+自动拉流已完成；剩余 RTSP backchannel/组播真机收流、ONVIF 真机。
9. EngineContext 已加入 `StreamApi` 注入，RTSP/SRT/WT/RTMP server 已迁移；剩余 HTTP/Event/DB 注入和其余插件（2 天）。
10. gRPC TLS + Bearer token 已完成；SQLite `PRAGMA user_version` 迁移已完成；剩余 mTLS、Postgres、连接池（2 天）。

### P2（业务/运维/商业化，2–4 周）

## 6. 不能声明“完成”的清单

- SVC 未实现；
- WHEP/WHIP 仅 webrtc-rs 客户端媒体面通过，浏览器/FFmpeg 互操作与 30s 稳定性未验收；
- 100K 未验证；
- LL-HLS 多码率/fMP4 加密/字节范围、GB28181 真实录像/PTZ 未验收；
- QUIC 媒体 relay 仍为 stream，不是 datagram；分片分配已实现，跨主机媒体路由/多级 cluster 未完成；
- Room/Live/Meeting 完整业务未闭环；官方商业授权模型（在线激活/计费）未对齐；
- 10K 真实流为同内容 tee，不能代表异构 10K 摄像头；
- 未做与官方 V6 同机同场景的 P50/P99/24h 浸泡对比。

## 7. 建议执行顺序

```text
TWCC → 100K 多机
      → LL-HLS/GB28181 深度 → Room/Admin → SVC（需外部编码器）
```

SVC 与 100K 依赖外部资源，应与其它项并行准备环境；在资源到位前，不以“完全对标”对外表述。

## 2026-11-23 性能优化

- HTTP-FLV 使用 FlvTag::write_to 复用缓冲；
- DispatchReader::recv() 异步等待，去掉 20ms 轮询；
- 延迟采样 1/64，减少全局锁竞争；
- Dispatcher 改为 broadcast 共享环；
- HTTP-FLV 热路径拆到 `src/http_flv.rs`，核心路径补充逐段注释；
- 新增 `scripts/perf_gate.ps1` 与 `docs/DELIVERY.md`；
- 本机 10K viewers：10000/0，CPU 45.3%，p99 254.5ms，内存 13.7MB；
- 20K viewers：16333/20000，服务端 CPU 51.4%，瓶颈在单客户端/Windows。
